# VELOMAX — MCV 측정 오차 보정 기능 개발 명세서

> 문서 유형: 기존 `PRD.md`에 추가하는 **데모 버전 기능 명세**  
> 문서 버전: v1.0 / 작성일: 2026-11-20  
> 적용 종목: **스쿼트·데드리프트** (이번 비교 실험의 실제 종목은 미확정)  
> 범위: **MCV 보정의 모의 적용 및 계산 재실행**, 원본·보정 결과 비교, 기록 관리, 단위 테스트  
> 제외: Gemini·Firebase·외부 API, 실제 영상 자동 MCV 추출, 다수 대상자 대상 타당도 검증  
> **중요:** 본 보정계수는 **단일 사례의 측정점 3개**에서 추정한 *실험용 수치*이며, 일반화된 검증 계수가 아니다.

## 1. 개발 목표

VELOMAX가 산출한 MCV와 GymAware 기준 MCV를 비교하여 관찰된 **체계적인 과대측정 경향**을 데모 화면에서 보정해 보고, 보정 전후의 부하–속도 선형회귀와 e1RM을 **동일한 계산 엔진**으로 다시 산출한다.

다음 두 종류의 오차를 **혼동하지 않는다**.

- **MCV 측정 오차:** VELOMAX 속도 측정값과 GymAware 측정값 사이의 차이. 본 문서의 보정식이 직접 대상으로 삼는 부분.
- **e1RM 추정 오차:** 최대하 세 중량의 회귀직선을 최대근력 영역까지 외삽하고 MVT를 적용할 때 생기는 오차. MCV 보정만으로 반드시 없어지지 않는다.

**개발 원칙:** 실제 측정값 160kg에 결과를 억지로 맞추는 보정식은 구현하지 않는다. 160kg·0.25m/s는 **사례 비교용 기준값**이지 일반 사용자의 MVT나 자동 조정 목표가 아니다.

### 2.1 원본 데이터

|---|---:|---:|---:|---:|---:|
| 1 | 96 | 0.85 | 1.28 | +0.43 | +50.59% |
| 2 | 128 | 0.60 | 0.89 | +0.29 | +48.33% |
| 3 | 144 | 0.51 | 0.74 | +0.23 | +45.10% |
| **평균** | — | — | — | **+0.3167** | **+48.01%** |

추가 비교값: **실제 1RM=160kg**, 실제 1RM 수행 MCV=**0.25m/s**, 기존 VELOMAX e1RM≈**181.5kg**.  
기존 e1RM은 **MVT=0.30m/s**를 적용한 경우 재현된다(세 원본점을 회귀한 뒤 계산한 값 약 181.52kg). 현재 앱에 실제로 어떤 MVT가 설정되어 있는지는 코드에서 별도 확인해야 한다.

### 2.2 수치로 확인되는 현상

- 원본 MCV의 GymAware 대비 **MAE = 0.3167m/s**.
- 서로 다른 중량에서도 상대오차가 약 45~51%로 나타나 **비례적 편향 가능성**이 있다.
- 원인으로는 거리 환산·카메라 원근·추적 대상(관절 vs 바벨)·구심성 구간 검출 등을 검토할 수 있으나, **현재 데이터만으로 특정 원인을 확정할 수 없다**.

## 3. 1차 보정: MCV 비례 보정

### 3.1 기본 수식

속도 원본을 `v_raw`, 기준장비 속도를 `v_ref`라 할 때:

\[
v_{corrected}=k\,v_{raw}
\]

원점을 통과하는 최소제곱 비례 보정계수:

\[
k=\frac{\sum_i v_{raw,i}v_{ref,i}}{\sum_i v_{raw,i}^{2}}
\]

본 사례 데이터로 계산한 값은 **`k = 0.6713676505`**이다. 시연용 설정에서는 설명이 쉬운 **`k = 0.67`**을 기본으로 사용한다. 이 둘 중 어떤 계수를 적용했는지 결과와 기록에 명시한다.

개별 속도 비율(기준/원본): 영상 1 **0.6641**, 영상 2 **0.6742**, 영상 3 **0.6892**.

### 3.2 기본 계수 0.67 적용 결과

| 중량 | GymAware | VELOMAX 원본 | 보정 MCV=`원본 × 0.67` | 보정값−기준 |
|---:|---:|---:|---:|---:|
| 96kg | 0.8500 | 1.2800 | **0.8576** | +0.0076 |
| 128kg | 0.6000 | 0.8900 | **0.5963** | −0.0037 |
| 144kg | 0.5100 | 0.7400 | **0.4958** | −0.0142 |

- 보정 전 MAE: **0.3167m/s**
- 보정 후 MAE: **0.0085m/s**
- 위 개선폭은 **보정계수를 산출한 바로 그 세 데이터에서 평가한 적합 결과**다. 다른 영상·사람·운동에 대한 기대 정확도로 소개하지 말 것.

### 3.3 선택적 비교 방법: 절편이 있는 선형 보정

이번 데이터에서만 맞춘 참고 회귀식:

\[
v_{ref}\approx0.63191763\,v_{raw}+0.04037323
\]

현재 데모의 **기본 알고리즘에는 포함하지 않는다**. 비교용 설명·향후 실험 후보로만 남긴다. 데이터가 3개뿐이라 비례 보정보다 더 낫다고 결론 내릴 수 없다.

## 4. 2차 분석: 보정한 MCV로 e1RM 재계산

### 4.1 기존 계산 방법 유지

중량 `L_i(kg)`과 MCV `v_i(m/s)`의 최소제곱 선형회귀:

\[
\hat v=aL+b,\qquad e1RM=\frac{MVT-b}{a}
\]

- 회귀 계산은 기존 `src/services/analysis.js`의 **기존 검증 함수**를 재사용한다.
- MVT는 `src/config/mvt.demo.js`에 정의된 `운동 종목 × 사용자 유형`의 **데모 설정값**을 사용한다.
- **보정 과정에서 MVT 값을 자동 변경하거나 실제 1RM 0.25m/s로 덮어쓰지 않는다.**
- `MVT=0.25m/s`는 **이번 사례의 가상 비교 시나리오**에서만 사용할 수 있다.

### 4.2 계산 검산표 (최소제곱, 소수 표시 반올림)

| 속도 자료 | 회귀 기울기 `a` | 절편 `b` | MVT 0.30 적용 e1RM | MVT 0.25 적용 e1RM |
|---|---:|---:|---:|---:|
| VELOMAX 원본 | −0.01138393 | 2.36642857 | **181.52kg** | 185.91kg |
| VELOMAX × 0.67 | −0.00762723 | 1.58550714 | **168.54kg** | 175.10kg |
| GymAware 기준 | −0.00718750 | 1.53500000 | **171.83kg** | **178.78kg** |

**MVT=0.30**을 유지한 비교:

- 기존 추정 181.52kg → 보정 후 168.54kg.
- 실측 160kg과의 차이: 기존 **+21.52kg(13.45%)** → 보정 후 **+8.54kg(5.34%)**.
- 그러나 이 결과 역시 **이번 사례에 한정**되며, 보정된 MCV를 사용해도 정확한 1RM을 보장하지 않는다.

**실제 1RM 속도 0.25m/s**로 비교한 경우:

- GymAware의 96/128/144kg 자료로만 만든 회귀직선은 160kg에서 약 **0.385m/s**를 예측한다.
- 실제 160kg에서 측정한 속도는 **0.25m/s**다.
- 따라서 GymAware 기준값을 그대로 사용해도 `MVT=0.25`일 때 e1RM **178.78kg**으로 과대추정된다. 즉 **속도 측정 정확도 ≠ e1RM 추정 정확도**다.

### 4.3 R² 해석 주의

- VELOMAX 원본 3점의 회귀 R² ≈ **0.9963**.
- 모든 MCV에 같은 양의 비례계수를 곱하면 **R²는 그대로**다.
- 높은 R²는 **관측한 세 중량의 직선 적합도**를 나타낼 뿐, 측정 범위 밖 1RM 예측의 정확도를 보증하지 않는다.

## 5. 데모 웹서비스에 추가할 기능 범위

### 5.1 기능 요구사항

| ID | 우선순위 | 요구사항 |
|---|---|---|
| CAL-01 | P0 | 분석 시 사용하는 MCV의 **원본 값 보존**. 보정값으로 원본을 덮어쓰지 않음 |
| CAL-02 | P0 | 사용자에게 `원본 / 실험용 보정(×0.67)` 선택 옵션 제공 |
| CAL-03 | P0 | 보정 사용 시 보정된 3개 MCV로 **회귀식·R²·e1RM을 다시 계산** |
| CAL-04 | P0 | 결과 표에 원본 MCV, 보정 MCV, 보정 적용 여부와 계수 표시 |
| CAL-05 | P0 | 보정 조건·모델 버전을 결과 저장/히스토리/인쇄 보고서에 저장 및 표시 |
| CAL-06 | P0 | **단일 사례·미검증 계수**라는 경고 배지 항상 표시 |
| CAL-07 | P0 | GymAware에서 입력한 **이미 기준화된 MCV를 중복 보정하지 않도록** 출처 검증 |
| CAL-08 | P1 | 개발자용 `GymAware 사례 불러오기` 버튼 제공(96·128·144kg 샘플, 참조값 포함) |
| CAL-09 | P1 | 보정 전후 e1RM을 같은 화면에서 비교하는 2개 카드/그래프 제공 |
| CAL-10 | P1 | 회귀 진단 메시지(기울기, 외삽, R² 과신 경고) 제공 |

기존 `PRD.md`의 데모 범위는 유지한다. **영상 업로드만으로 자동 MCV를 산출했다고 표시하지 않는다.** Gemini·Firebase 연동 및 실제 영상 분석은 추가하지 않는다.

### 5.2 보정 적용 대상 판별

기존 `velocitySource: "demo" | "manual"` 항목은 **입력 방식**을 의미하므로 유지한다. 대신 *측정값의 원래 출처*를 별도 필드로 추가한다.

- `velocityOrigin: "velomax_raw"` → 보정 실험 옵션 선택 가능.
- `velocityOrigin: "gymaware"` → 기준장비 MCV이므로 보정 불가(원본 사용).
- `velocityOrigin: "demo_other"` → 별도 설정 없이는 보정 불가.
- `velocityOrigin: "unknown"` 또는 미입력 → 보정 불가(원본 사용).

**기본 설정은 보정 OFF**로 한다. 사용자가 `VELOMAX 원본 측정값`임을 확인하고 `실험용 보정`을 선택했을 때만 적용한다. 지금 데모에서 VELOMAX 영상 분석은 구현되지 않으므로 보정 기능의 출처 표기는 **사용자 수동 입력 또는 고정 테스트 예시**일 수 있다.

### 5.3 UI 배치

`분석 입력 화면`:

- `[ ] 실험용 MCV 보정 적용 (×0.67)` 체크박스: 기본 해제.
- 보정 적용 시 `원본 값 × 0.67로 보정하는 데모 기능이며, 1개 사례에서만 계산된 미검증 계수입니다.` 안내.
- 출처가 GymAware/미상/기타이면 체크박스 비활성화 및 이유 표시.
- 사례 로드 버튼을 누르면 중량·VELOMAX 원본 MCV 3개를 채우고, 비교 기준인 GymAware 3개는 **참조값으로만** 보관.

`결과 화면`:

- 원본 3점 vs 보정 3점 표(단위 m/s).
- `원본 e1RM`, `보정 e1RM`, `적용 MVT`, `보정계수 및 출처` 표시.
- 그래프의 측정점과 회귀선에 **원본/보정 범례** 표시. 과도한 복잡도를 피하기 위해 그래프 토글 방식도 허용.
- `보정 전후 차이`는 **실측 1RM을 모르는 일반 사용자에게 정확도 개선이라고 표현하지 않는다**.

`히스토리·PDF`:

- 선택된 최종 e1RM 외에 원본·보정 두 결과를 함께 기록.
- 추세 그래프에 서로 다른 보정 모드를 섞어 표시하면 분석 조건 차이 경고.
- 현재 PDF 출력은 기존 PRD처럼 **HTML 보고서 + 브라우저 인쇄(`window.print`)** 방식 유지.

## 6. 권장 데이터 모델 및 코드 구조

### 6.1 설정 파일 `src/config/calibration.demo.js`

```js
/**
 * [VELOMAX 보정 기능의 데모 설정]
 * 이 보정계수는 사용자 제공 단일 사례 3점으로부터 산출한 미검증 파일럿 계수다.
 * 실제 영상 측정의 정확도나 타당도가 확보되었다는 뜻이 아니다.
 */
export const MCV_CALIBRATION_DEMO = Object.freeze({
  id: "gym-aware-pilot-001",
  version: "pilot-2026-11-20-v1",
  method: "proportional",
  factor: 0.67,
  enabledByDefault: false,
  allowedOrigin: "velomax_raw",
  status: "UNVALIDATED_SINGLE_CASE",
  sampleSize: 3,
  notice: "단일 사례 기반 미검증 MCV 보정계수입니다."
});
```

### 6.2 순수 함수 `src/services/calibration.js`

```js
import { MCV_CALIBRATION_DEMO } from "../config/calibration.demo.js";

/**
 * [기능] 원본 MCV 세 점에 실험용 비례 보정계수를 적용한다.
 * [입력] points: [{ loadKg, mcvMs }, ...] / options: { enabled, velocityOrigin }
 * [반환] [{ loadKg, rawMcvMs, usedMcvMs, correctionApplied }, ...]
 * [주의] GymAware·출처 불명 데이터는 중복 보정하지 않는다.
 * [설계] 원본 배열/원본 객체를 변경하지 않는 순수 함수로 구현한다.
 */
export function calibrateMcvPoints(points, options = {}) {
  const enabled = options.enabled === true;
  const eligible = options.velocityOrigin === MCV_CALIBRATION_DEMO.allowedOrigin;

  // 사용자가 명시적으로 보정을 켰으나 출처가 맞지 않는 경우 오류를 반환한다.
  if (enabled && !eligible) {
    throw new Error("VELOMAX 원본 MCV에만 실험용 보정을 적용할 수 있습니다.");
  }

  return points.map(({ loadKg, mcvMs }) => {
    // 원본 값 유효성 검사는 기존 분석 입력 검증 함수를 먼저 호출하도록 구성한다.
    const usedMcvMs = enabled ? mcvMs * MCV_CALIBRATION_DEMO.factor : mcvMs;
    return { loadKg, rawMcvMs: mcvMs, usedMcvMs, correctionApplied: enabled };
  });
}
```

**연결 지점(개념):**

1. 입력값에 대한 기존 유효성 검사 수행.
2. `calibrateMcvPoints(points, {enabled, velocityOrigin})` 호출.
3. 기존 계산 엔진에 `usedMcvMs`를 `mcvMs`로 매핑한 점 배열 전달.
4. **보정 ON/OFF 모두 동일한** 회귀·MVT·e1RM 계산 함수 사용.
5. 원본 결과도 같은 계산 함수를 통해 별도 산출하여 비교 화면에 제공.

- 위 JSON은 **예시 필드만 발췌**한 것이며, 기존 측정 ID·사용자 ID·날짜·종목·회귀식·R² 등은 유지한다.
- `e1rmKg`는 분석에 실제로 적용한 모드의 값을 기록한다.
- **종목은 사용자 정보에 없으므로 예시에서 의도적으로 생략**했다. 시연 시 스쿼트 또는 데드리프트 중 사용자가 선택한 종목을 유지하고, 특정 종목의 검증 자료라고 표시하지 않는다.
- 구형 히스토리 레코드에는 `calibration.enabled=false`를 기본으로 **안전하게 해석**한다. 과거 기록에 보정값을 소급 덮어쓰지 않는다.
- `localStorage`를 계속 사용한다. **Firebase/서버/외부 API 추가 금지.**

---

## 7. 입력 검증 및 예외 처리

- 입력은 서로 다른 **3개 중량(kg)**과 양수인 MCV(m/s) 3개가 필요하다.
- 중량·속도는 유한한 숫자여야 한다. NaN/Infinity/문자/음수/누락 시 계산 중단.
- 회귀 기울기가 0 이상이면 e1RM을 계산하지 않고 입력값 검토 안내.
- e1RM이 최대 측정 중량 이하이거나 비정상적으로 큰 경우 기존 PRD 검증 규칙을 준수.
- R²가 높아도 e1RM 실제 오차를 알 수 없다는 고지를 유지.
- 출처가 `gymaware` 또는 불명확한 경우 보정 ON을 **차단**한다.
- 보정계수 `0.67`은 `src/config/calibration.demo.js` 한 곳에서만 관리하고 계산 중 하드코딩하지 않는다.
- 소수점 표시는 UI에서만 반올림한다. 계산·저장에는 충분한 정밀도를 유지한다.
- 실측 1RM이 없는 일반 사용자는 정확도 비교·오차율을 산출할 수 없으므로 결과에 임의 표시하지 않는다.

아래 값은 **테스트 픽스처**로 사용한다. 허용 오차는 별도 명시가 없다면 수치 비교에서 `1e-4` 수준으로 설정한다.

## 10. 주의사항 및 후속 연구

### 지금 할 수 있는 것

- **이 단일 사례의 세 중량**에서 웹서비스 MCV가 GymAware보다 높았다는 사실을 수치화.
- 시험용 `×0.67`을 적용해 결과가 어떻게 달라지는지 시각화.
- 원본과 보정된 MCV를 이용한 회귀·e1RM 차이를 일관되게 계산.

### 지금 단정할 수 없는 것

- 이 계수가 다른 사람, 다른 종목, 카메라 각도, 스마트폰, 촬영 속도, 바벨 궤적에서도 유효하다는 주장.
- 이 계수가 VELOMAX의 실제 영상 측정 기술 오류를 **근본적으로 해결했다**는 주장.
- 보정 후 e1RM이 실제 1RM에 항상 더 가깝다는 주장.

### 추후 정식 검토 시 수집할 데이터

- 각 대상자·종목·중량별 **동일 반복의 영상 MCV / GymAware MCV** 쌍.
- 촬영 FPS, 카메라 각도·거리, 거리 환산 설정, 추적 대상, 구심성 구간 검출 방식.
- 실측 1RM, 실측 1RM 속도, 운동경력·숙련도 분류 기준.
- **계수 산출용 데이터와 검증용 데이터를 분리**하여 보정 전후 MAE·편향·RMSE를 비교.

> **최종 원칙:** 이 기능은 `VELOMAX 영상 MCV → (선택적 실험용 속도 보정) → 기존 선형회귀 → 기존 MVT → e1RM`이라는 **추가 계산 단계**다. MVT 자체를 조정하거나, 실측 160kg에 맞게 결과를 강제로 바꾸는 알고리즘이 아니다.
