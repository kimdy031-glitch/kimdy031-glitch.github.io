# PRD — 영상 기반 e1RM 계산 웹서비스 (Demo MVP)

> 문서 버전: v1.0  
> 문서 상태: 데모 개발 기준서  
> 작성일: 2026-11-19  
> 핵심 원칙: **외부 API·Firebase 없이 단독 실행되는 데모**, **가상 데이터의 명확한 표시**, **한국어 주석을 통한 코드 가독성**

---

## 1. 프로젝트 개요

### 1.1. 프로젝트명

**부하–속도 선형회귀모델을 활용한 영상 기반 e1RM 계산 웹서비스 — 데모 버전**

### 1.2. 한 줄 소개

스쿼트 또는 데드리프트의 서로 다른 세 중량과 MCV(평균 구심성 속도)를 입력하면, 부하–속도 선형회귀식을 이용해 추정 최대근력(e1RM)을 계산하고 운동 목적별 권장 중량 및 측정 히스토리를 보여주는 웹서비스의 **인터랙티브 시연용 프로토타입**.

### 1.3. 데모의 목표

1. 회원가입/로그인부터 분석·결과·히스토리·보고서까지 **사용자 흐름 전체를 시연**한다.
2. 가입 정보에 따라 사용자를 **일반인 / 운동인**으로 자동 분류한다.
3. **스쿼트 / 데드리프트**만 지원한다.
4. 세 중량의 MCV를 이용해 **실제로 동작하는 선형회귀 및 e1RM 산출 로직**을 구현한다.
5. Firebase, Gemini 등이 없어도 주요 UI와 탐색·그래프·기록 기능을 체험할 수 있게 한다.
6. 향후 Gemini·Firebase를 연결하기 쉽게 기능 경계를 명확하게 분리한다.
7. 모든 개발 코드에 **이해하기 쉬운 한국어 주석을 필수로 작성**한다.

### 1.4. 데모의 성격 및 정직성 원칙

이 버전은 **정밀한 AI 영상 측정 제품이나 검증된 최대근력 평가 도구가 아니다.**

- 운동 영상을 업로드할 수 있지만, **업로드 영상의 실제 움직임에서 MCV를 자동 산출하지 않는다.**
- 데모는 **시연용 샘플 MCV**를 불러오거나 **사용자가 알고 있는 MCV를 직접 입력**하여 결과를 계산한다.
- `Gemini 분석 중`이라는 표현으로 실제 Gemini 호출을 가장하지 않는다. 영상 섹션에는 **“데모: 실제 영상 분석 미연동”**을 표시한다.
- 데모 MVT는 추후 선행연구와 VBTcoach 자료로 검토할 **임시 설정값**이며, 학술적으로 검증된 기준값인 것처럼 표기하지 않는다.
- 결과지의 설명 문구는 규칙 기반 템플릿으로 생성하고 **“데모 자동 생성 해석(실제 Gemini 미연동)”**을 표시한다.
- 서비스 전반에 **“데모 측정값은 실제 트레이닝 처방 또는 최대근력 판정에 사용하지 마세요.”**라는 안내를 제공한다.

### 2.2. 이번 데모에서 제외할 기능 (Out of Scope)

- **Firebase Authentication, Firestore, Storage, Hosting 연동**.
- **Gemini API 또는 기타 AI/클라우드 API 호출**.
- 실제 동영상으로부터 **자동 관절점 추출, 바벨 추적, 구심성 구간 검출, MCV 자동 측정**.
- MediaPipe 등 실제 영상 추적 라이브러리의 필수 도입.
- 실제 회원 인증, 비밀번호 재설정, 메일 인증, 외부 계정 소셜 로그인.
- 서버/DB 구성, 결제 기능, 클라우드 동기화.
- 자동 이메일 발송, PDF의 클라우드 업로드·공유 링크 발급.
- 벤치프레스 및 그 외 추가 종목.
- 개인별 실측 MVT, 동작 자동 분류, 실시간 카메라 분석.
- GymAware와의 비교, 실제 1RM과의 비교 등 **연구 수준의 정확도·타당도 검증**.

### 2.3. 구현 경계

- **실제로 계산되는 것:** 입력한 MCV → 선형회귀 계수 → e1RM → 상대강도별 중량 → 변화량/변화율.
- **모의 처리되는 것:** 계정 인증, 회원 분류(정해진 규칙 기반), AI 영상 분석 상태/샘플 MCV, AI 결과 해석, 클라우드 저장.
- 데모의 모의 처리 내용은 시연 화면과 코드에서 반드시 구별할 것.

## 3. 대상 사용자 및 사용자 분류

### 3.1. 주요 사용자

- 개인 운동 데이터를 체계적으로 관리하려는 일반인.
- 체계적인 선수 훈련에 참여하거나 선수 경력이 있는 운동인.
- 향후 사용 대상: 스포츠 현장 트레이너, 퍼스널 트레이너 등.

### 3.2. 회원가입 입력 항목

| 항목 | 필수 여부 | 형식 | 비고 |
|---|---|---|---|
| 이름/닉네임 | 필수 | 문자열 | 결과지 표시 |
| 이메일 | 필수 | 이메일 형식 | 데모 로그인 식별자 |
| 비밀번호 | 데모 선택 | 문자열 | 실제 보안 인증이 아니므로 **실제 비밀번호 사용 금지** 안내 |
| 성별 | 필수 | 선택형 | 남성/여성/응답하지 않음 등 |
| 나이 | 필수 | 정수 | 입력 범위 검증 |
| 운동경력 | 필수 | 선택형 | 예: 1년 미만/1~3년/3년 이상 |
| 운동 참여 형태 | 필수 | 선택형 | 일반 운동/선수 또는 체계적인 선수 훈련 |

- 필수 개인정보는 회원가입 또는 최초 프로필 등록에서만 입력한다. 이후 측정 시작 시 반복 입력하지 않는다.
- 이메일 중복 여부는 데모용 로컬 계정 목록에서 확인한다.
- 실제 서비스와 달리 **실제 비밀번호·민감한 개인정보를 입력하지 말라**는 안내를 항상 표시한다.

### 3.3. 자동 분류 규칙 — 데모 전용

- `운동 참여 형태 = 선수 또는 체계적인 선수 훈련`이면 **운동인**.
- 그 외에는 **일반인**.
- 운동경력은 프로필에 별도 저장하고 결과지에 표시한다.
- 가입 완료 시 사용자의 분류 결과를 확인 메시지에 표시한다.
- 프로필 수정 시 분류를 다시 계산한다.
- 이 구분은 **데모 운영상 분류일 뿐, VBTcoach의 Novice/Elite 연구 기준과 자동으로 동일하다고 간주하지 않는다.**
- 향후 실제 MVT 적용 시에는 문헌의 대상자 정의에 맞는 별도 분류 규칙을 재정의한다.

### 3.4. 원클릭 데모 계정

로그인 화면에 다음 버튼을 제공한다.

| 버튼명 | 데모 사용자 | 분류 |
|---|---|---|
| `일반인 계정으로 체험` | 가상 일반인 | 일반인 |
| `운동인 계정으로 체험` | 가상 선수 훈련 참여자 | 운동인 |

- 버튼 클릭 시 비밀번호 입력 없이 즉시 로그인한다.
- 두 계정에는 **서로 다른 샘플 기록**을 배치해 히스토리를 비교할 수 있게 한다.
- 사용자 전환 시 기록이 섞이지 않아야 한다.
- 새로고침 뒤에도 데모 로그인 상태를 유지할 수 있다.
- 로그아웃과 모든 데모 데이터 초기화 기능을 제공한다.

## 4. 사용자 흐름(User Flow)

```text
접속
 ├─ 데모 계정 1클릭 로그인
 └─ 로컬 데모 회원가입 → 사용자 자동 분류 → 로그인
        ↓
대시보드
 ├─ 새로운 분석
 │    ↓
 │  운동 종목 선택(스쿼트/데드리프트)
 │    ↓
 │  서로 다른 3개 중량 입력 및 영상 3개 선택(영상은 선택 사항)
 │    ↓
 │  MCV 제공 방식 선택
 │    ├─ [데모 샘플 MCV 불러오기] → ‘영상 미분석’ 배지
 │    └─ [MCV 직접 입력]          → ‘사용자 입력’ 배지
 │    ↓
 │  데이터 유효성 검사
 │    ↓
 │  선형회귀 및 일반인/운동인 데모 MVT 적용
 │    ↓
 │  e1RM 결과 + 그래프 + 목적별 권장 중량
 │    ↓
 │  결과 저장 → 히스토리 / 보고서 / PDF로 저장(인쇄)
 ├─ 이전 측정 기록 조회
 └─ 마이페이지 → 회원정보 수정 / 로그아웃
```

**핵심 UX 원칙:** 영상 파일 업로드가 없어도 샘플값 또는 수동 MCV만으로 전체 흐름을 끝까지 시연할 수 있어야 한다. 영상은 UI 시연용이며 계산 입력값으로 오인되지 않도록 명확히 구분한다.

## 5. 화면 상세 요구사항

### 5.1. 화면 A — 로그인/회원가입

- 서비스명, 핵심 설명, `데모 버전` 표시.
- 원클릭 데모 계정 버튼 2개.
- 일반 회원가입/로그인 폼은 **서버가 없는 가상 계정 기능**임을 명시.
- 회원가입 시 필수항목 검증, 자동 분류 메시지 표시.
- 데모 회원의 비밀번호는 실제 비밀번호를 요구하거나 저장하지 않는 방식을 우선한다. 입력 필드를 연출할 경우 어떤 보안 인증도 제공하지 않는다고 고지하고 값은 저장하지 않는다.

### 5.2. 화면 B — 메인 대시보드

- 상단: 현재 로그인한 사용자, `일반인` 또는 `운동인` 배지.
- 본문: `새로운 e1RM 분석` CTA.
- 카드: 최근 스쿼트 e1RM, 최근 데드리프트 e1RM, 최근 측정일.
- 차트 또는 미니카드: 두 종목의 최근 근력 변화.
- 히스토리, 마이페이지 이동.
- 최초 접속 시 샘플 데이터 존재 여부와 데모 설명을 안내.

### 5.3. 화면 C — 종목 선택

- 스쿼트(Squat), 데드리프트(Deadlift) 카드 2개만 활성화.
- 종목마다 촬영·동작 조건을 간단히 설명.
- 다른 종목이나 벤치프레스는 선택지로 제공하지 않음.

### 5.4. 화면 D — 영상/중량/MCV 입력

- 서로 다른 세 중량에 대해 다음 입력 영역을 각각 제공:
  - 중량(바벨 포함 총 중량, kg), 양수 및 중복 확인.
  - 영상 파일 업로드(선택), 파일명/파일 크기/미리보기 표시.
  - 대표 MCV(m/s) 입력 또는 시연용 샘플 MCV 채우기.
- 동영상 미리보기는 `URL.createObjectURL()` 등 브라우저 기능으로 구현.
- 영상은 서버에 업로드하지 않으며, 저장소에 원본 영상을 영구 보관하지 않는다.
- 영상 업로드를 하더라도 **MCV 입력란을 자동 채운 것이 실제 분석 결과가 아님**을 명확히 표시.
- `데모 샘플 불러오기`: 종목 및 사용자 유형에 따라 미리 만든 일관된 예시 중량·MCV를 채운다.
- `MCV 직접 입력`: 각 중량의 MCV를 이용자가 직접 수정할 수 있다.
- 분석 버튼 클릭 시 값 검증 후 계산 화면으로 이동.
- 보정용 기준 물체 UI는 이번 버전의 필수 기능에서 제외하고 ‘추후 지원’ 안내만 가능.

### 5.5. 화면 E — 분석 과정

- 처리 단계별 진행 표시: 입력 검증 → 대표 MCV 확정 → 선형회귀 → MVT 적용 → 결과 표시.
- 이 진행 단계는 브라우저 내 실제 계산을 반영해야 함.
- AI 분석을 실행하는 듯한 가짜 로딩이나 `Gemini 연결 성공` 문구 사용 금지.
- 화면 하단에 `현재 데모는 실제 영상을 분석하지 않습니다.` 안내.

### 5.6. 화면 F — 분석 결과

필수 시각화:

1. **추정 최대근력(e1RM)**: 가장 크게 표시, 단위 kg.
2. **입력한 3개 부하–MCV 점**: X축 중량(kg), Y축 MCV(m/s).
3. **최소제곱 회귀직선**: 관측점과 함께 표시.
4. **MVT 기준선 및 e1RM 교차점**: 데모 기준값임을 강조.
5. **회귀식과 R²**: 기울기 `a`, 절편 `b`, 결정계수 `R²` 표시.
6. **중량별 입력 MCV 표**: 입력의 출처(샘플/직접 입력) 표시.
7. **권장 중량 표**: 최대근력·근비대·근파워·근지구력별 예시 범위.
8. **결과 저장 / 다시 분석 / 결과지 보기** 버튼.

상단 고정 배지: `DEMO · 실제 영상 미분석 · MVT 임시값`.

### 5.7. 화면 G — 히스토리

- 현재 계정·종목별 측정 기록 목록.
- 측정일 순 e1RM 변화 선그래프.
- 직전 측정 대비 변화량 `현재 e1RM − 직전 e1RM` (kg).
- 변화율 `(현재 − 직전) / 직전 × 100` (%), 직전 값이 0이면 계산하지 않음.
- 각 기록별 분석 조건(MCV 출처, MVT 값, 모델 버전) 확인.
- 기록 삭제 및 전체 데모 데이터 초기화.
- 조건이 달라진 기록을 비교할 때 `분석 조건이 달라 직접 비교에 주의` 안내.

### 5.8. 화면 H — 결과 보고서

## 6. 분석 및 계산 사양

### 6.1. 입력값

분석에 필요한 최소 데이터:

```js
// 예시: 실제 영상에서 추출한 값이 아닌, 사용자가 입력하거나 샘플로 불러온 값입니다.
const input = {
  exercise: "squat",          // "squat" | "deadlift"
  userGroup: "general",       // "general" | "athlete"
  velocitySource: "demo",     // "demo" | "manual"
  points: [
    { loadKg: 40, mcvMs: 0.90 },
    { loadKg: 60, mcvMs: 0.70 },
    { loadKg: 80, mcvMs: 0.50 }
  ]
};
```

> 위 3점은 수학적 계산 테스트용 **가상 데이터**이다.

### 6.2. 선형회귀

세 중량을 `Lᵢ`, 각 중량의 대표속도를 `vᵢ`라고 할 때 최소제곱법으로 다음 식을 구한다.

\[
\hat v = aL+b
\]

\[
a=\frac{\sum_i(L_i-\bar L)(v_i-\bar v)}{\sum_i(L_i-\bar L)^2}, \qquad b=\bar v-a\bar L
\]

- `a`는 음수여야 정상적인 역방향 부하–속도 관계에 부합한다.
- R²를 별도로 계산해 표시한다.
- **R²가 높다는 이유만으로 실제 e1RM 정확성이 검증됐다고 표현하지 않는다.**

### 6.3. MVT 설정 — 데모와 정식 버전 구분

- 기본설계는 `운동 종목 × 사용자 유형` 조합별 MVT 4개를 참조한다.
- 이번 데모에서는 개발자가 `src/config/mvt.demo.js`의 **시연용 임시 숫자**를 사용하도록 한다.
- 임시값은 `status: "DEMO_PLACEHOLDER"`와 함께 보관하고 UI에 명확히 표시한다.
- 임시값에 실제 논문 출처가 있는 것처럼 문헌명·DOI를 임의로 생성하지 않는다.
- 정식 버전의 연구 기반 MVT는 **VBTcoach 설명 및 원문 논문을 확인한 후**, 동일한 운동 방식·속도 지표(MCV)·사용자 분류 기준인지 검토하여 별도 등록한다.
- 사용자 분류(`general`/`athlete`)와 문헌의 Novice/Elite 구분은 현재 동일한 개념으로 확정하지 않는다.
- 개발용 MVT 예시 값 자체는 학술적 기준으로 사용하지 못하도록 테스트/화면 모두에 경고를 넣는다.

### 6.4. e1RM 계산

\[
\boxed{e1RM=\frac{MVT-b}{a}}
\]

- `a = 0`, 양의 기울기, 유효하지 않은 숫자, 서로 같은 중량, 비현실적인 계산 결과 등의 경우 계산을 중단하고 수정 안내를 표시한다.
- e1RM이 최대 측정 중량보다 작거나 같은 경우 결과를 확정하지 않고 입력값 검토를 요청한다.
- 외삽 범위가 큰 경우 `측정 구간 외 추정값` 경고를 표시한다.
- 화면 수치는 반올림해서 표시하되 내부 계산은 원본 정밀도 유지.

### 6.5. 목표별 권장 중량

- `근력`, `근비대`, `근파워`, `근지구력` 4개 카테고리를 표시.
- 상대강도 범위는 `src/config/trainingZones.demo.js`에서 설정하는 **데모용 예시값**으로 관리.
- 사용자에게 `시연용 강도 예시이며 개인화된 전문 처방이 아닙니다` 표시.
- 각 범위의 중량은 `e1RM × 최소/최대 상대강도`로 계산.
- 표시용 중량 단위(예: 2.5kg 단위 반올림)는 설정값으로 분리.

### 6.6. 시연용 데이터 생성 규칙

- **무작위 `Math.random()`로 매번 다른 MCV 결과를 만들지 않는다.**
- 종목·사용자 유형별로 고정된 샘플 데이터 세트를 준비한다.
- 값은 중량 증가에 따라 속도가 대체로 감소하도록 구성한다.
- 동일한 입력을 다시 분석하면 항상 동일한 결과가 나와야 한다.
- 데이터 자체와 화면에 `SIMULATED / 시연용 예시 데이터` 표시.

## 9. 코딩 및 주석 규칙 — 필수

**개발 과정에서 사용자가 소스코드를 직접 열어 구조와 기능을 이해할 수 있어야 한다. 아래 규칙은 선택이 아니라 완료 조건이다.**

### 9.1. 필수 주석 규칙

1. **모든 JavaScript 파일 상단**에 해당 파일의 목적과 책임을 한국어 주석으로 설명한다.
2. **모든 주요 함수 위**에 역할, 매개변수, 반환값, 부작용을 한국어 주석 또는 JSDoc으로 기록한다.

4. `localStorage` 저장 키와 스키마 정의, 더미 데이터 생성 이유를 주석으로 남긴다.

6. HTML의 큰 화면/섹션에는 구역 주석을 작성한다.
7. CSS는 주요 레이아웃 및 상태별 스타일을 구역별 한국어 주석으로 나눈다.

10. 단순한 문법을 반복 설명하는 무의미한 주석보다 **왜 이렇게 설계했는지**를 설명하는 주석을 우선한다.

## 14. 비기능 요구사항

### 성능
- AI 처리나 영상 업로드가 없으므로 주요 수치 계산은 브라우저에서 즉시 완료될 것.
- 그래프 렌더링 중 화면이 멈추지 않을 것.
- 동영상은 미리보기만 하고 프레임별 대용량 처리를 수행하지 않을 것.

### 보안·개인정보
- 가상 계정과 샘플 데이터를 우선 사용.
- 실제 비밀번호, 결제정보, 건강정보 등 민감 데이터 수집 금지.
- localStorage는 보안 DB가 아님을 고지.
- 외부 네트워크 요청, 인증키 보관, 영상 전송 없음.
- ‘데모 초기화’로 기록을 지울 수 있도록 지원.

### 정확성·표시
- 계산값과 시연용 입력값을 구별.
- MVT, 권장 강도 구간은 **임시 시연용 설정**으로 표시.
- 계산식과 원 입력값을 항상 검토할 수 있어야 함.
- 결과는 운동 지도·의료 진단의 근거가 아니라는 고지를 포함.

> **이 PRD를 기준으로 HTML/CSS/Vanilla JavaScript 데모 웹서비스를 구현하라.** 외부 API와 Firebase는 연결하지 말고, 실제 Gemini·AI 영상 분석을 수행했다고 주장하지 말라. 로그인은 일반인/운동인 원클릭 가상 계정으로 가능하게 하고, 회원가입 정보에 따라 자동 분류되는 가상 가입 흐름을 구현하라. 스쿼트와 데드리프트만 지원한다. 영상은 선택·미리보기만 수행하며, 실제 계산은 시연용 샘플 MCV 또는 직접 입력한 MCV를 기반으로 최소제곱 선형회귀와 데모 MVT를 사용한다. 결과 그래프·권장 중량·사용자별 히스토리·인쇄용 결과지를 연결하라.
